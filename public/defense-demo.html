Actions

Fare + concurrency in action
Fare = Base Fare + (OSRM Distance × Per-km Rate)
Example Zone 1: ₱25 base + ₱8/km → ~₱41 for ~2 km.
One open booking per passenger (Pending through In Progress) — enforced in UI and API.

Scene 8 · Configuration

Admin Manages Fare Zones and Rates

A
System Administrator
Admin · Fare Configuration
admin
Page: /admin/fares
Zone rates are the source of all fare calculations. Changing them here affects every future booking immediately — no code change needed.
Actions
1
Go to Fare & Zones → two pre-configured zones: Zone 1 – Town Center (₱25 base, ₱8/km) and Zone 2 – Extended Area (₱35 base, ₱10/km)
2
Click the pencil (Edit) icon on Zone 1 → dialog opens pre-filled with current name, description, base fare, and per-km rate
3
Update base fare to ₱28.00 → Save → zone card updates immediately with the new rate
4
Fill Add New Zone form: name, description, base fare, per-km rate → Add Zone → new card appears in the list
5
Click the trash (Delete) icon on the new zone → confirmation dialog → Delete → zone removed instantly
RBAC in action
Only the Admin can access the Fare & Zones page. Drivers and passengers do not see this module in their navigation. Fare updates take effect on the next booking — the system always reads the current zone configuration at booking time.

Admin Response Actions
4
Switch to admin@demo.com → go to /admin/sos
5
Active Emergency card appears with red border — passenger name, phone, GPS coordinates, message, timestamp
6
Click Mark as Resolved → alert moves to resolved section, red border removed
Failsafe by design
If GPS permission is denied, the SOS is still submitted using a fallback Socorro coordinate — the alert is never blocked. Admin Dashboard shows the unresolved SOS count in the summary cards. Only the Admin can resolve alerts.

Role Enforcement
Admin, Driver, and Passenger each see only their own modules. No accidental access, no workarounds possible.
🗺️
Interactive Map Booking
Leaflet map, OSRM route distance, road snapping, destination picker, and optional preferred-driver selection.
📡
Live Driver Tracking
Passengers see the driver's live position on a map during Accepted → In Progress trips.
🚦
Booking Concurrency
One open ride per passenger; one active trip per driver — enforced in UI and API.
💰
Auto Fare Computation
Zone-based formula: Base Fare + Distance × Per-km Rate. No negotiation, no ambiguity — the fare is shown before booking.
🛡️
Driver Verification
Drivers are PENDING by default. Only an Admin can verify or suspend them. Unverified drivers cannot accept rides.
🆘
SOS Emergency
One-tap SOS with GPS coordinates. Always accessible from sidebar. Admin resolves alerts from a dedicated management page.

Real-Time Analytics
Month-over-month revenue, booking counts, and top driver performance. Always current — no manual reports needed.
